# 코드 구조와 수정 위치

`app.py`는 앱을 생성하고 로컬 서버를 시작합니다. `notifier.create_app()`은 설정, 저장 경로, 발송 서비스를 묶어 Flask 앱을 만듭니다. 웹 화면은 서비스에 작업을 요청하고, 서비스는 엑셀·메시지·API·저장 모듈을 조합합니다.

## 파일별 역할

| 파일 | 역할 | 이 파일을 수정하는 경우 |
|---|---|---|
| `app.py` | 실행 진입점 | 실행 주소·포트 변경 |
| `notifier/__init__.py` | 앱 생성과 모듈 연결 | 앱 설정·구성 변경 |
| `notifier/settings.py` | 환경 변수 해석, 실행 모드, 공개용 설정 표시 | 설정 항목·기본값 변경 |
| `notifier/models.py` | 학생·리포트·미리보기 데이터 구조 | 데이터 항목 추가 |
| `notifier/excel.py` | 기존 엑셀 양식 읽기 | 시트명·열 이름·입력 양식 변경 |
| `notifier/input_rules.py` | 문자열·날짜·숫자·번호 정규화 | 입력 표현이나 허용 형식 변경 |
| `notifier/templates.py` | 3종 템플릿 본문과 공통 항목 | 승인된 안내 본문 변경 |
| `notifier/preview.py` | 학생 매칭, 항목 검증, 메시지 생성·수정·통계 | 업무 규칙 변경 |
| `notifier/aligo.py` | 토큰 발급, 발송 요청, 응답 해석 | 외부 API 연동 변경 |
| `notifier/delivery_store.py` | SQLite 요청 예약과 중복 이력 | 중복 판단·요청 상태 변경 |
| `notifier/storage.py` | 운영 경로, 업로드, JSON, CSV | 파일 저장 방식 변경 |
| `notifier/service.py` | 미리보기·수신 확인·발송·로그 흐름 연결 | 업무 처리 순서 변경 |
| `notifier/web.py` | HTTP 요청, 화면 안내, CSRF, 발송 전 확인 | 화면 조작과 안내 문구 변경 |
| `templates/index.html`, `static/style.css` | 화면과 스타일 | 배치·표시·디자인 변경 |

## 분리한 이유

- 엑셀 파서와 메시지 생성은 Flask 요청·세션 없이 실행할 수 있습니다.
- API 모듈은 실제 전송을 담당하고, 서비스는 요청 이력과 로그 기록 순서를 관리합니다. 통신 오류를 발송 전 실패·명시적 거절·결과 불명확으로 구분하는 규칙은 유지했습니다.
- 저장 모듈은 파일을 다루고 웹 화면에 직접 알림을 띄우지 않습니다. 서비스가 돌려준 결과를 웹 화면에서 표시합니다.
- 설정과 파일 경로는 앱마다 따로 갖습니다. 테스트가 실제 운영 폴더나 다른 앱의 미리보기·중복 이력을 사용하지 않도록 합니다.

## 운영 데이터 호환

기존 v7과 동일한 `runtime/demo`, `runtime/live` 경로, 미리보기 JSON 항목, SQLite 테이블과 메시지 지문 규칙을 사용합니다. 코드 파일을 나누면서 기존 v7 발송 이력의 형식을 바꾸지 않았습니다. 운영 이력을 보존하려면 실제 `runtime/` 폴더를 유지해야 합니다.

기존 v6 이력의 자동 이관 기능을 추가한 것은 아닙니다. v6에서 처음 옮길 때는 [운영 안내](usage.md)를 따릅니다.

## 검사

프로젝트 폴더에서 `python -m unittest discover -s tests -v`를 실행합니다. 기존의 동명이인·중복 발송·입력 오류 검사 29개와 앱 인스턴스 사이의 설정·미리보기·발송 이력이 섞이지 않는 검사 1개를 유지합니다. 외부 API는 모의 응답을 사용합니다.
