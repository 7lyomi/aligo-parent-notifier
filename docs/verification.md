# v7.1.0 수정 및 검증 기록

로컬 확인일: 2026-09-11. GitHub CI 실행 시각과 결과는 [Tests 실행 기록](https://github.com/7lyomi/aligo-parent-notifier/actions/workflows/tests.yml)에서 확인합니다.

## 수정 내용

- 학생ID 우선 매칭과 학생명 교차 확인. ID 없는 동명이인, 중복 ID, 같은 학생의 중복 리포트를 차단합니다.
- SQLite에 발송 요청을 먼저 예약합니다. 반복 클릭·반복 요청·재시작 후 동일 요청을 막습니다. 결과를 확인하지 못한 요청도 재전송하지 않습니다.
- 날짜, 휴대전화번호, 퍼센트, 단어 개수, 테스트 구분·레벨·점수·평균을 검증합니다. Excel의 퍼센트 저장값과 표시 서식을 함께 해석합니다.
- 선택·전체 발송 모두 유형별 본인 번호 수신 확인을 요구합니다. 저장하지 않은 수정 내용과 오래된 화면에서는 바로 전송하지 않습니다.
- 실제 학원명, 기존 샘플 개인정보와 운영 파일을 공개본에서 제외했습니다. 설정 예시의 자격증명은 비워두고, 기본 실행은 외부 API를 사용하지 않는 데모입니다.

## 수행한 검사

기능별 코드 분리 후 Linux / Python 환경에서 `python -m unittest discover -s tests -v`를 실행하여 **30개 검사 모두 통과**했습니다. 기존 29개 검사의 동작 확인 항목을 유지하고 앱 인스턴스 사이의 상태 분리 검사 1개를 추가했습니다. 외부 API는 모의 응답으로 대체했으며 이 자동 검사에서는 실제 메시지를 보내지 않았습니다.

| 범위 | 확인한 동작 |
|---|---|
| 학생 연결 | 같은 이름·다른 ID, ID와 이름 불일치, 중복 ID, ID 없는 기존 파일, 중복 리포트, 발송 제외 |
| 입력 | 숫자와 퍼센트 서식 차이, 허용 범위, 잘못된 날짜·번호, 테스트 구분 누락, 데모 번호의 운영 차단 |
| 웹 요청 | Flask 테스트 클라이언트의 실제 샘플 업로드·미리보기, CSRF, 오래된 화면, 저장 전 발송 보류 |
| 발송 흐름 | 데모의 외부 API 미호출, 선택·전체 발송의 수신 확인, 템플릿 설정 변경 시 확인 무효화, 본인 테스트 번호 사용 |
| 중복·오류 | 접수 후 반복, 타임아웃, 결과 코드 없는 응답, 명시적 거절 후 재시도, 동시 예약, 로그 기록 실패 |
| 행 수 | 300행 처리와 CSV 기록, 500건 초과 요청의 분할 |
| 앱별 상태 | 별도 설정·저장 경로로 생성한 앱 사이에 미리보기·발송 이력이 섞이지 않음 |

300행 검사는 기능 검사이며 성능·부하 시험이나 실제 300명 발송 실적을 뜻하지 않습니다.

## 지속적인 검사

`.github/workflows/tests.yml`은 PR과 main 변경 시 Ubuntu 환경에서 Python 3.10·3.12로 같은 회귀 검사를 실행하도록 구성했습니다. 외부 알림톡 자격증명을 사용하지 않고 저장소 읽기 권한으로 실행합니다. CI 결과는 위 실행 기록에 남으며, 실제 휴대전화 수신 검사를 대신하지 않습니다.

## 작성자의 운영 확인

작성자는 운영본의 **Windows 실행과 실제 알림톡 수신을 확인**했다고 밝혔습니다. 원장님에게 3종 안내 유형을 반영한 최종본을 전달했고, 현재 편리하게 잘 사용하고 있다는 후기를 받았습니다.

이 현장 확인은 작성자가 제공한 운영 경험입니다. 이번 코드 구조 정리의 동작 유지는 위 자동 검사로 확인했습니다. 새로운 실제 메시지를 보내는 재검증은 수행하지 않았습니다.

## 비용 비교 확인

작성자가 제공한 당시 단가(장문 문자 25.9원, 알림톡 6.5원)에 동일한 월 발송량 9,000건(300건 × 30일)을 적용했습니다.

| 항목 | 계산 결과 |
|---|---:|
| 장문 문자 | 25.9 × 9,000 = 233,100원 |
| 카카오 알림톡 | 6.5 × 9,000 = 58,500원 |
| 절감액 | 174,600원 |
| 절감률 | 약 74.9035%, 반올림하면 약 74.9% |

위 계산으로 **약 75% 절감**이라는 표현의 산술 근거를 확인했습니다. 청구서를 독립적으로 대조한 감사 결과를 뜻하지 않습니다.

## 이력 보존

이번 분리는 기존 v7의 운영 경로, 파일 형식과 중복 식별 규칙을 유지합니다. v6 발송 이력의 자동 이관은 포함하지 않습니다.

중복 방지는 이 프로그램의 로컬 이력이 남아 있는 범위에 적용됩니다. 본문·학생ID·수신번호를 변경하거나 이력을 삭제하면 동일 요청으로 인식하지 않을 수 있습니다. 응답이 불확실한 경우 알리고 발송 내역을 먼저 확인해야 합니다.
