# 실행 및 운영 안내

아래 파일 경로와 명령어는 프로젝트 최상위 폴더를 기준으로 합니다.

## 처음 실행하기

1. Python 3.10 이상을 설치합니다. Windows 설치 시 `Add python.exe to PATH`를 선택합니다.
2. ZIP을 새 폴더에 완전히 압축 해제합니다.
3. `install_windows.bat`를 실행합니다. 필요한 패키지를 설치하고 `.env`를 만듭니다.
4. `start_demo.bat`를 실행합니다. 브라우저에서 `http://127.0.0.1:5050`이 열립니다.
5. **가상 샘플 불러오기**를 누릅니다. 12명의 가상 학생으로 메시지를 확인하고 시뮬레이션할 수 있습니다.

데모는 API를 호출하지 않고 비용도 발생하지 않습니다. `DEMO-0001` 같은 번호는 실제 발송 모드에서 차단합니다. 서버 창은 사용하는 동안 열어두세요.

## v6에서 실제 운영용으로 옮길 때

기존 v6 폴더는 보관하고 v7.1.0을 새 폴더에 설치합니다. 기존 데이터와 설정을 덮어쓰지 않습니다. v6 발송 이력은 자동 이관되지 않으므로, 새 버전의 첫 발송 대상은 기존 발송 내역과 대조해주세요.

1. `samples/sample_students.xlsx`의 헤더를 참고해 실제 운영 엑셀을 준비합니다. 학생DB와 데일리 리포트에 **학생ID**를 같은 값으로 입력합니다. ID는 이후에도 유지합니다.
2. 새 `.env`에 기존 API Key, 사용자 ID, 등록 발신번호, Sender Key, 승인 템플릿 3개를 옮깁니다.
3. `ACADEMY_NAME`에 기존 승인 템플릿의 대괄호 안 학원명을 정확히 입력합니다. 기존 템플릿의 나머지 본문·줄바꿈은 유지했습니다.
4. `ALIGO_TEST_PHONE`에 본인 휴대전화번호를 입력합니다.
5. `APP_MODE=live`, `ALIGO_TEST_MODE=Y`로 설정하고 `start_windows.bat`를 실행합니다. API 테스트와 미리보기를 확인합니다.
6. 실제 수신 확인 시 `ALIGO_TEST_MODE=N`으로 바꾸고 앱을 재시작합니다. 해당 유형의 학생 1명 선택 후 **본인 번호 1건 테스트**를 누릅니다. 이 버튼은 보호자 번호 대신 `ALIGO_TEST_PHONE`으로 요청합니다.
7. 휴대전화에서 실제 수신을 확인한 뒤 **유형별 본인 번호 수신 확인**에서 해당 유형의 확인 기록을 남깁니다. 일반 발송은 그 유형의 수신 확인이 있어야 가능합니다. 선택·전체 발송 모두 동일한 규칙을 적용합니다.

다른 학원명이나 승인 템플릿을 사용하는 경우 승인된 본문과 프로그램 본문이 정확히 일치해야 합니다. 알리고의 등록 IP 등 기존 계정 조건도 그대로 적용됩니다. `.env` 수정 후에는 재시작해야 합니다.

## 기존 v7에서 v7.1.0으로 옮길 때

v7.1.0은 기존 v7과 같은 설정·데이터 형식·중복 식별 규칙을 사용합니다. 같은 폴더에 파일을 섞지 않도록 새 폴더에 압축을 풀고, 기존 프로그램을 종료한 상태에서 `.env`와 `runtime/` 전체를 복사합니다. 기존 폴더는 백업으로 보관합니다.

`APP_DATA_DIR`로 별도 저장 경로를 사용했다면 그 경로와 데이터를 유지합니다. 두 버전을 동시에 실행하지 않으며, 학생ID·수신번호·본문을 바꾸면 기존 요청과 다른 요청으로 처리될 수 있습니다. 코드 구조 변경 설명은 [아키텍처](architecture.md), 버전 차이는 [변경내역](../CHANGELOG.md)을 참고합니다.

## 입력 규칙

| 항목 | 처리 |
|---|---|
| 학생ID | ID로 매칭하고 학생명도 교차 확인합니다. 중복 ID는 파일을 차단합니다. |
| ID 없는 기존 파일 | 이름이 유일할 때만 연결합니다. 동명이인은 임의로 연결하지 않습니다. |
| 중복 리포트 | 같은 학생·날짜·테스트구분이 중복되면 해당 행들을 차단합니다. |
| 날짜 | 유효한 학습일을 `YYYY-MM-DD`로 입력합니다. |
| 과제수행률 | 0~100%. Excel 퍼센트 서식 `90%`(저장값 0.9)를 올바르게 읽습니다. 일반 서식 숫자 90과 문자 `90%`도 90%이며, 일반 서식 숫자 1은 1%입니다. |
| 단어 전체·오답 | 0 이상 정수. 오답 수는 전체 수를 넘을 수 없습니다. |
| 테스트 구분 | 없음·주간·월간. 구분이 비어 있는데 레벨·점수·평균이 있으면 직접 선택해야 합니다. |
| 주간·월간 | 레벨은 정수 1~7, 점수·평균은 0~100입니다. |
| 테스트 없음 | 남아 있는 레벨·점수·평균은 메시지에 포함하지 않습니다. |
| 수신번호 | 국내 휴대전화번호. Excel에서 문자 형식으로 저장해 앞자리 0을 유지합니다. |
| 발송여부 | Y는 대상, N은 제외입니다. |

화면에서 내용을 수정하면 **변수 저장 / 미리보기 갱신** 후 다시 확인합니다. 저장하지 않고 발송을 요청해도 수정 내용을 먼저 표시하고 발송은 보류합니다.

## 중복 발송 처리

- 같은 **학생 식별값·날짜·수신번호·본문·실행 모드**는 한 번만 요청합니다. 본문을 실제로 수정한 경우에는 다른 요청으로 취급하므로 내용을 검수해야 합니다.
- 요청 직전에 SQLite에 원자적으로 예약합니다. 이중 클릭, 반복 요청, 앱 재시작 후에도 이력이 유지됩니다.
- 응답 대기 중 종료되거나 결과가 불명확하면 `pending` 또는 `unknown` 상태로 보관하고 자동 재시도를 막습니다. 알리고 발송 내역에서 먼저 확인해야 합니다.
- 발송 전 인증 실패 또는 API의 명시적 요청 거절은 재시도할 수 있습니다. 수신자별 최종 결과는 별도 확인해야 합니다.
- **미리보기 비우기**와 엑셀 재업로드는 발송 이력을 삭제하지 않습니다. 데모와 운영 기록은 분리됩니다.
- `runtime/live/deliveries.sqlite3`는 운영 이력입니다. 삭제·교체하면 중복 방지의 과거 기록이 사라집니다. 이 앱의 이력은 다른 프로그램이나 알리고 웹사이트에서 보낸 요청까지 추적하지는 않습니다.

## 파일과 개인정보

- `app.py`: 실행 진입점
- `notifier/`: 엑셀·메시지·API·저장·웹 처리를 역할별로 나눈 패키지
- `notifier/input_rules.py`: 숫자·날짜·연락처 입력 규칙
- `notifier/delivery_store.py`: SQLite 요청 예약과 중복 처리
- `samples/sample_students.xlsx`: 공개 가능한 가상 데이터 12명
- `tests/test_sender.py`: 네트워크를 대체하는 회귀 검사
- `runtime/`: 실행 후 생성되는 실제 설정 외 데이터·업로드·로그·발송 이력

API 키는 `.env`에서 읽습니다. `.gitignore`는 `.env`, 운영 엑셀, 미리보기, 로그, 데이터베이스를 제외하고 가상 샘플만 허용합니다. `.gitignore`는 이미 Git에 등록한 파일을 지우는 기능이 아니므로 기존 저장소로 옮길 때는 등록 파일도 확인해야 합니다. 실제 운영 로그에는 수신번호와 본문이 포함되므로 공개하지 마세요.

## 검사 실행

설치 후 프로젝트 폴더에서 다음을 실행합니다.

```bash
python -m unittest discover -s tests -v
```

가상 샘플, 동명이인, 중복 ID·리포트, 퍼센트, 잘못된 입력, Flask 업로드·미리보기, 선택·전체 발송 보호, 요청 중단, 중복 예약, 300행 및 500건 초과 분할 등을 검사합니다. 모든 외부 API 호출은 모의 응답으로 대체합니다.

운영본의 Windows 실행·실제 알림톡 수신은 작성자가 확인했습니다. 코드 분리 후 자동 검사 범위와 확인 주체는 [검증 기록](verification.md)에 기록합니다.
