# 학부모 알림톡 업무 자동화

학원에서 반복하던 학생별 학습 안내를 **엑셀 입력 → 메시지 생성 → 미리보기·수정 → 알림톡 발송**으로 연결한 프로젝트입니다.

기존 프로젝트를 **300명 규모 학원**의 실제 업무에 적용해 **메시지 발송 비용을 약 75% 절감**했습니다. 이 저장소에는 개인정보를 제거하고 입력 검증과 중복 발송 방지를 보강한 **v7**을 담았습니다.

## 문제

학원에서는 학생별 등원 상태, 과제 수행률, 단어 시험과 테스트 결과를 학부모에게 안내해야 했습니다. 학생마다 내용이 달라 개별 메시지를 반복해서 준비해야 했고, 문자 발송 비용도 계속 발생했습니다.

목표는 운영자가 학생별 내용을 확인할 수 있으면서, 반복 작성과 발송에 드는 부담을 줄이는 것이었습니다.

## 기존 업무 방식

1. 학생별 학습 현황을 확인합니다.
2. 각 학생의 내용을 학부모 안내 문자로 정리합니다.
3. 학부모에게 개별 문자를 발송합니다.

공통 안내 형식이 있어도 학생별 값을 바꿔야 했습니다. 테스트가 있는 날과 없는 날에는 안내 항목도 달라졌습니다.

## 해결 방법

학생 정보와 학습 기록을 엑셀에서 읽고, 학생별 메시지를 자동으로 생성하도록 구현했습니다. **테스트 없음·주간·월간**에 맞춰 승인된 알림톡 템플릿을 선택하며, 운영자가 화면에서 내용을 확인하고 수정한 뒤 발송합니다.

메시지 전달에는 알리고의 카카오 알림톡 API를 사용합니다. Windows PC에서 실행하는 로컬 웹 프로그램으로 구성했습니다.

## 주요 기능

| 기능 | 동작 |
|---|---|
| 엑셀 불러오기 | 학생DB와 데일리 리포트를 통합 파일 또는 별도 파일로 읽습니다. |
| 학생 연결 | 학생ID로 연결하고 이름을 교차 확인합니다. ID 없는 동명이인은 확인 대상으로 남깁니다. |
| 3종 메시지 생성 | 테스트 없음·주간·월간에 따라 본문과 변수를 구성합니다. |
| 미리보기·수정 | 등원, 과제, 단어 수, 테스트 결과를 수정하고 최종 본문을 확인합니다. |
| 입력 오류 확인 | 날짜·전화번호·퍼센트·개수·점수의 누락과 잘못된 범위를 확인합니다. |
| 선택·전체 발송 | 대상 행을 선택하거나 입력 확인이 끝난 전체 행을 요청합니다. |
| 중복 요청 방지 | SQLite에 발송 이력을 남겨 같은 요청의 반복 전송을 막습니다. |
| 본인 번호 테스트 | 유형별로 본인 휴대전화의 수신을 확인한 후 일반 발송을 진행합니다. |
| 결과 기록 | API 요청 결과를 CSV로 남깁니다. 요청 접수와 실제 수신은 구분합니다. |
| 데모 모드 | 가상 학생 12명으로 외부 API 호출과 요금 부과 없이 체험합니다. |

## 내가 한 판단과 개선 과정

### 업무 요구를 프로그램 흐름으로 구체화

학원 운영자의 개별 안내 업무를 파악하고, 요구사항과 피드백을 바탕으로 엑셀 입력부터 발송까지의 흐름을 구성했습니다. 학생마다 다른 내용을 공통 템플릿과 변수로 나누고, 테스트 유무에 따라 안내 항목을 달리하도록 구현했습니다.

### 발송 전 사람이 확인하는 단계 유지

학생별 내용은 실제 학부모에게 전달되므로, 자동 생성 후에도 운영자가 본문을 읽고 수정할 수 있도록 미리보기를 두었습니다. v7에서는 수정 내용을 저장하고 다시 확인한 뒤 발송하도록 이 단계를 보강했습니다.

### Windows 로컬 앱으로 구현

현재 프로그램은 사용자의 PC에서 파일을 읽고 브라우저로 조작합니다. 운영자가 사용하는 Windows·엑셀 환경에 맞춰 설치 및 실행 배치 파일을 제공하며, 별도의 서버 운영 없이 사용할 수 있는 구조입니다.

### 코드 리뷰를 반영한 v7 개선

| 발견한 문제 | 개선한 내용 | 판단 이유 |
|---|---|---|
| 이름만으로는 동명이인을 구분하기 어려움 | 학생ID 우선 연결, 이름 교차 확인, 모호한 행 차단 | 학습 내용과 수신자를 정확히 연결하기 위해 |
| 반복 클릭이나 재시도로 같은 메시지가 다시 요청될 수 있음 | 요청 전 SQLite 예약, 재시작 후에도 이력 유지 | 화면 버튼 제어만으로 중복 요청을 막기 어려워서 |
| 타임아웃 때 실제 발송 여부를 알 수 없음 | 확인 대기 상태로 보관하고 자동 재시도 차단 | 이미 접수된 메시지를 다시 보내는 일을 피하기 위해 |
| Excel의 90%가 내부적으로 0.9로 저장됨 | 숫자 값과 퍼센트 서식을 함께 해석 | 표시된 의미가 메시지에도 그대로 반영되도록 |
| 테스트 구분 누락·잘못된 점수 등이 메시지에 들어갈 수 있음 | 유형별 필수 항목과 값 범위 검증 | 발송 전에 오류를 발견하도록 |
| 운영 파일을 그대로 공유하면 개인정보가 포함됨 | 가상 샘플, 빈 설정 예시, 운영 파일 제외 규칙 제공 | 다른 사람도 프로젝트 흐름을 안전하게 확인하도록 |

기존 운영 프로젝트와 이번 v7 수정·검증은 구분합니다. v7의 코드 개선과 회귀 검사에는 AI 코딩 도구를 활용했습니다.

## 실행 방법

### 데모 실행

1. **Python 3.10 이상**을 설치합니다. Windows 설치 시 `Add python.exe to PATH`를 선택합니다.
2. 프로젝트 ZIP을 내려받아 완전히 압축 해제합니다.
3. `install_windows.bat`를 실행합니다. 최초 설치에는 패키지 다운로드를 위한 인터넷 연결이 필요합니다.
4. `start_demo.bat`를 실행합니다.
5. 브라우저의 `http://127.0.0.1:5050`에서 **가상 샘플 불러오기**를 누릅니다.

기본 모드는 실제 메시지를 보내지 않는 데모입니다. 가상 학생 12명의 메시지를 확인하고 선택·전체 시뮬레이션을 실행할 수 있습니다.

### 실제 운영 및 검사

실제 발송에는 알리고 계정, 등록 발신번호, Sender Key, 승인 템플릿과 본인 테스트 번호 설정이 필요합니다. [실행 및 운영 안내](docs/usage.md)의 설정·이관 순서를 따릅니다. v6 발송 이력은 v7에 자동 이관되지 않습니다.

회귀 검사는 프로젝트 폴더에서 실행합니다.

```bash
python -m unittest discover -s tests -v
```

Linux/Python 환경에서 **29개 검사 통과**를 확인했습니다. API는 모의 응답으로 대체했으며, Windows 설치 실행과 실제 알림톡 수신은 별도 확인이 필요합니다. [검증 기록](docs/verification.md)에 수행 범위를 남겼습니다.

## 성과

| 항목 | 결과 |
|---|---|
| 적용 현장 | **300명 규모 학원**의 학부모 안내 업무 |
| 발송 비용 | 기존 방식 대비 **약 75% 절감** |
| 업무 개선 | 학생별 안내 생성, 미리보기·수정, 발송 요청과 결과 기록을 하나의 흐름으로 연결 |

학원 규모와 비용 절감률은 기존 프로젝트의 실제 운영에 대해 작성자가 확인한 수치입니다. 300명은 프로그램 사용자·동시 접속자 수가 아니며, 비용 절감률은 이 저장소의 데모 시험 결과가 아닙니다. 업무 시간 절감률은 여기에 수치로 제시하지 않았습니다.

## 저장소 안내

- `app.py`: 엑셀 연결, 로컬 웹 화면, 발송 흐름
- `input_rules.py`: 입력값 정규화와 검증
- `delivery_store.py`: SQLite 기반 요청 예약과 중복 처리
- `samples/sample_students.xlsx`: 동명이인 예시를 포함한 가상 학생 12명
- `tests/test_sender.py`: 외부 API를 대체하는 회귀 검사
- `docs/`: 실행 안내, 검증 기록, 화면 자료

실제 API 키, 운영 엑셀, 학부모 연락처와 발송 로그는 포함하지 않습니다. 실행 후 생성되는 `runtime/`에는 운영 데이터가 저장되므로 버전 관리에서 제외합니다.
